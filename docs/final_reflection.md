# Final Reflection

1. **Traceability**: Git allows me to track which code version produced which benchmark result.
2. **Collaboration**: GitHub acts as a central hub for sharing these benchmarks with other researchers.
3. **Branching**: Using branches ensures that experimental extraction logic doesn't break the working main script.
4. **Pull Requests**: PRs allow for a "peer review" phase to verify benchmark logic before merging.
5. **Reproducibility Files**: These files ensure that another student can replicate my benchmark exactly.
6. **Version Tags**: A tag like v1.0.0 creates a permanent reference point for this specific experiment.
7. **Citation Files**: Providing a CITATION.md ensures that my benchmarking effort is properly credited.
8. **PhD Practice**: This workflow mirrors the rigorous documentation required for high-impact cybersecurity research.
